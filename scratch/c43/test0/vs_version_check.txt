Conclusions:
(a) start key: every 2019 tag (1.0-1.15) uses S = int_le(sha256(pbkdf2_hmac_sha512(seed,'VanitySearch',2048,64))). No tag uses plain sha256(seed).
    Verified byte-for-byte: tool's own hash/sha512.cpp+sha256.cpp from tags 1.0 (MSVC intrinsics stubbed) and 1.15 compiled with
    vs_hash/startkey.cpp -> identical to the Python formula for the 4 Phase-0 seeds and 'controlseed'. => no third start formula added.
    v1.15 -kp (key pair from seed) = S itself (CPU t=0, j=0) -> already covered.
(b) CPU offset: S + thId<<64 in every tag (thId = 0..nbCPU-1).
(c) GPU offsets: TWO schedules.  1.0-1.4: keys[i] = S + i<<96 (single GPU, no GPU term)  <-- NOT in the earlier script.
    1.5-1.15: keys[i] = S + i<<80 + (0x80+g)<<112, g = index in -gpuId list. incr is measured from keys[i] (group start; 1.15 computes
    the centre point but reports j*GRP_SIZE + incr relative to keys[i]); negative incr = negated key; endo e applies lambda^e afterwards.
(d) rekey: option absent in 1.0-1.10; in 1.11-1.15 'uint64_t rekey = 0' (disabled) -> deterministic schedule.
Default GPU threads = 1024 x #SM in every tag (16*MP groups x 64 thr in 1.0-1.5.1; 8*MP x 128 from 1.6) -> i < 2^17 covers <= 128 SMs.
